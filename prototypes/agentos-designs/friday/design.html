01 / The interface contract

A persistent companion. A changing canvas.

The selected direction combines the quiet Friday Canvas with the useful project workspace from Operations Studio. The entire interface uses white surfaces, neutral grey borders, charcoal text, and generous space. Status can use restrained semantic colour; there is no blue background wash.

Friday home→Companies→Company & project cards→Project home→Kanban / Agent Map
  • Agent OS, top left, always returns to Friday home. Browser Back and breadcrumbs move through the same navigation history.
  • Companies, projects, decisions, people, tasks, and evidence are centre-canvas destinations. Clicking them changes the route and the content; it does not open a navigation modal.
  • Friday is large at home and docks bottom right when content opens. One conversation and voice session survive that change.
  • The default navigation stays small: Companies, Decisions, Workforce, Agent Map; search and the audit trail are utilities. The left navigation remains visible throughout working views, including Audit Trail and Workforce, and retains the selected company/project context.
  • Decisions and blockers surface proactively. Routine progress stays quiet and inspectable.
02 / Friday’s presence

Talk first. Open the conversation when you want it.

The orb is made entirely of animated dots: a loose spherical point cloud with depth, slow rotation, and a small pulse. It is an identity and conversation-state indicator. Unlike the work graph, its particles do not claim to represent business records.

The home conversation is part of the page layout, beside the orb, not a fixed bottom-left overlay. On narrow screens it flows below the orb. It can be minimised and retains the same conversation used by the right-side drawer when Friday is docked. Greetings, discussion, and questions do not automatically navigate. The top-left Agent OS mark uses a small version of the same animated dot sphere. Microphone capture stops when the page loses visibility, the user pauses voice, or the session ends.

Preview boundary: this design uses browser speech recognition and speech playback where available, with local sample commands and replies. Browser recognition may use the browser’s speech provider. It is not connected to the real Friday agent, a paid voice API, or production companies. The full application must use the real conversation pipeline and its explicit subscription/connection configuration.

03 / Work has a clear hierarchy

Portfolio → company → project → task → evidence.

Companies are independent ventures. Each company overview shows its purpose, CEO, project cards, decisions, team, work summary, and recent activity. A company may have multiple applications and non-application projects. Departments are optional labels for stable functions; projects remain the places where outcomes and tasks are organised.

Project cards show the name, purpose, department, accountable lead/team, tasks left, tasks in motion, and completed work. Every card opens a genuine project-scoped workspace; the launch campaign must have its own marketing tasks, not a reused customer-portal board.

The right rail offers short useful updates, not another chat window. Opening a task or artefact uses the main canvas with a reliable breadcrumb back to the workspace. Application assets retain their repository and environment bindings independently of the projects working on them.

New and existing work: new-company onboarding accepts a venture brief or an existing GitHub repository. Existing projects start with discovery of current work and commitments; they are not reset. Company creation, proposed staffing, operating limits, and repository adoption remain separate, reviewable steps. Draft companies and projects show honest empty states until work exists.

04 / The constellation, grounded in work

Every point can answer “what is this?”

The map has portfolio, company, and project scopes. Clickable nodes represent companies, projects, company-specific employee assignments, tasks, runs, sources, and artefacts. Lines have explicit meanings: ownership, assignment, delegation, access, observed use, or attached evidence.

  • Spiral and orbital layouts organise actual records; they never add filler dots to look busy.
  • Motion represents recorded activity. Permission to access a dataset and an observed read are distinct relationships.
  • Pan, zoom, fit, scope breadcrumbs, keyboard selection, and an inspector work at every level. Large maps group records with accurate counts and expand on demand.
  • The board and map use the same scoped work model, so task counts and status agree.
  • Missing or stale execution data is labelled. Show published analysis and provider-exposed events with their source; do not invent private internal reasoning.
  • Reduced motion replaces continuous animation with static emphasis while preserving all state information.
05 / Capabilities stay accessible

A simpler surface, with the operational depth intact.

  • Workforce: a table of employees, roles, company assignments, current work, skills, harness/model, and subscription seats, with clickable rows opening profiles. Company and project scopes filter the employee list; the global view shows everyone. Profiles retain instructions, capacity, and spend controls. Individual employee chat is scoped to what the owner can access.
  • Company profile: purpose, CEO, applications, operating mandate, resources, policies, and approvals. Company CEOs retain company-scoped authority.
  • Decisions: one portfolio inbox, filterable by company/project, with recommendation, exact proposed action, evidence, revision, and attributable outcome. Voice yes/no binds to a specific current proposal; ambiguity asks for clarification.
  • Routines and artefacts: retain their native ownership and persistence. Friday delegates recurring work to the right lead instead of becoming the scheduler.
  • Audit and search: company/project/task/employee filters, staffing and retirement history, skill adoption, execution actions, approvals, failures, and recovery records.
  • Platform changes: Friday can help change Agent OS only within an explicit user request. Finding a capability gap does not itself authorise a platform deployment.
  • Reusable canvas: first use registered tables, cards, charts, and reports. Save repeated layouts with typed, scoped data; custom generated code stays in an isolated sandbox without parent-app credentials.

Extension / Independent product

Models that are chosen from evidence.

Model Intelligence is a separate product, integrated into Agent OS. It has its own API, policies, evaluation history, SDK, storage and deployable package. Agent OS is its first host: Friday and company leads own the work, the service recommends a qualified model profile, and native Agent OS execution enforces permissions, seat capacity and limits.

Work stage→Qualified profiles→Recorded choice→Native execution→Verified result→Evaluated improvement

Several model profiles can share one subscription seat without duplicating its allowance. The system learns from first-pass quality, failed attempts, repairs, resource use and independent checks. Prompt, context and model changes are compared in controlled evaluations before a policy is promoted. Companies can pin their current version, adopt an improvement or roll it back.

The first execution milestone qualifies the actual account and automation mode. No model is treated as available just because its name appears in a catalog, and there is no automatic API or paid-overage fallback. Private company context remains scoped to its assignment.

Task Execution shows model choices and each attempt. Friday can surface policy comparisons and learning evidence on the canvas. The Agent Map now uses blue for companies/projects, violet for assignments, amber/cyan/green for task states, terracotta for evidence and teal for Friday, on white. A later optional model lens will have its own legend.

06 / From this design to the application

Build the interaction once; connect it to real work.

The current HTML is a design prototype. The production implementation should reuse Paperclip’s company, project, issue, routine, artefact, approval, execution, and workforce services. It should replace the dominant navigation/layout with an Agent OS frame rather than add another panel inside the existing shell.

  1. Persistent Agent OS frame. Add a portfolio-aware layout with the white token set, persistent Friday conversation/voice provider, centred home, inline left-side conversation, dock, right-side history drawer, and canvas route outlet. Keep the native advanced views accessible as secondary destinations.
  2. Shared navigation contract. Extend the existing Friday navigation helpers with typed company/project/task/decision targets, source context, breadcrumbs, and browser history. Both spoken navigation and clicks dispatch the same validated destination. Company access is checked before rendering.
  3. Companies and project workspaces. Bind real portfolio memberships and company records to company cards, project cards, overview counts, default project Home with activity, and a separate full-width Kanban board. Keep tasks single-assignee and reuse native task details and artefacts.
  4. Friday voice and conversation. Refactor the existing Friday voice controls into one persistent session with requesting/listening/processing/speaking/error states, audible replies, interruption, mute, transcript recovery, and typing fallback. Use current configured execution; never introduce an automatic paid fallback.
  5. Decisions, workforce, routines, and results. Connect each view to its real native service. Preserve permission boundaries, attribution, revision checks, source approval semantics, and seat configuration. Server confirmation determines the displayed outcome.
  6. Unified work graph. Build one authorised projection from the same scoped records as the workspace. Add incremental observed activity, coverage/staleness indicators, aggregation, filters, and synchronised selection. Keep runtime and company enforcement in their native owners.
  7. Generated and reusable content. Support typed Friday canvas requests using approved renderers, then reusable saved layouts. Add an isolated code-preview surface only when the registered components are insufficient.
  8. Verification and rollout. Verify the journeys below against real data, microphone/audio in supported browsers, permission failures, responsiveness, reduced motion, and activity reconnects. Release the new shell while retaining a route back to advanced Paperclip controls during migration.

Existing implementation anchors include Friday.tsx, FridayVoiceControls.tsx, FridayOrb.tsx, FridayWorkspace.tsx, FridayWorkGraph.tsx, and friday-navigation.ts. Their existing capabilities are inputs to the redesign, not proof that the new interaction model is already connected.

07 / What “working” must mean

Prove the complete journeys.

  1. Open Agent OS → see Friday home on a white background → tap Talk → microphone starts without a navigation modal → state becomes Listening only after capture starts.
  2. Say “show the decisions that need me” → hear a reply → see Decisions in the main canvas → Friday is docked → the same conversation remains available.
  3. Open Companies → choose any company → see all its project cards → open any project → see its own tasks and updates → switch Home / Kanban / Decisions / Agent Map / Routines without losing project context.
  4. Click another company in the left navigation → render that company centrally → click Agent OS → return home. Browser Back returns to the previous scope.
  5. Click Prefer to type at home → type a greeting or ordinary question → see the reply to Friday’s left without navigation or a modal. Then explicitly ask to open a project → Friday docks → click the orb → see the same history and type in the right drawer.
  6. Open company Decisions → see decisions grouped by project → open project Decisions → see only that project. Company/project Routines follow the same rule. Open Audit Trail or Workforce → retain the left navigation and scope.
  7. Open Workforce → inspect the employee table → click a row → open the full employee profile → return to the same workforce scope.
  8. Inspect a task, result, or map record → see its owner and company → return to its project. Counts agree across cards, boards, and maps.
  9. Approve or decline a decision → retain attribution and revision → show the confirmed outcome and audit event. Failed or uncertain submissions remain visibly unresolved.
  10. Test microphone denied, unsupported recognition, interrupted audio, hidden tab, stale data, empty company, no projects, missing permissions, narrow screens, keyboard-only interaction, and reduced motion.

Current verification boundary: the refined preview serves real HTML and JavaScript with fictional data. Module, route-scope, rendered-view, and DOM interaction checks passed locally, including inline chat without unwanted navigation, company/project Decisions and Routines, company Kanban, Audit navigation, and employee tables. Earlier voice-state simulations also passed. These checks do not prove visual rendering or physical audio behaviour. The in-app browser integration is currently failing before connecting, so visual rendering, real microphone capture, and audible playback have not been verified through it. Those checks remain required before treating this as a production-ready implementation.
